# Model and Proxy Guide

## Start with the definitions

This project uses public UIUC GPA course-term aggregates. The source is a course-term-instructor grade distribution, not a student table, registration-event table, or section table.

- `Students` is the count of final A+–F grade records after course completion, and the source field equals the sum of the A+–F grade bands. It is not registrations, unique students, or section enrollment. `W` is the count of formal `Withdraw` marks.
- The observed course-volume total is `Students + W` (the compatibility field `demand_proxy`). It is not intended sign-ups, registration requests, capacity, or waitlist.
- `w_mark_share = W / (Students + W)` is a derived W-mark share, defined only when counts are valid and the denominator is positive. It is not the W count and is not an official withdrawal rate.
- `grade_point_mean` is an estimated 4.0-style weighted mean from A+–F counts, not an official GPA.
- Example: with `Students=95` and `W=5`, the observed course-volume total is `100` and the W-mark share is `5/100=0.05` (5%). This is a descriptive ratio in the same observation frame.

## Time and historical features

Six calendar years contain 12 main terms (spring and fall each year), not six terms. Each prediction year uses only earlier information:

| Prediction year | History available | Same-term lag example |
| --- | --- | --- |
| 2022 | 2019–2021 | 2022 Spring uses 2019, 2020, 2021 Spring; 2022 Fall uses the corresponding Fall terms |
| 2023 | 2020–2022 | 2023 Spring uses 2020–2022 Spring; 2023 Fall uses 2020–2022 Fall |
| 2024 | 2021–2023 | 2024 Spring/Fall are truth-only holdout observations, not training data |

The continuity focus is the three-year 2021–2023 window; 2024 is a bridge year and truth-only holdout, not a replacement for that primary focus. The first two years train and the third year is held out. The independent trajectory uses stable key `Subject + Number`; Course Title is display-only and title changes are audited rather than split into variants. Special-topic handling is row-level: 3 special-only stable keys are fully outside the ordinary trajectory, while the 8 stable keys overlapping ordinary rows retain those ordinary rows. Ordinary courses use either term from each prior calendar year, while genuinely one-season courses use the same-season history.

The six-year backtest (2019–2024) is a separate, user-approved extension; it does not replace the primary analysis window. Its 2024 Spring, 2024 Fall, and all-scope metrics (AP, ROC-AUC, Brier, Precision, Recall, F1, balanced accuracy, Recall@20%, and TP/FP/FN/TN) must be read from the generated metrics table. The page reports both all observations and history-complete eligible coverage; incomplete-history rows are excluded from primary metrics. The continuity output includes each course's observed cells and exact period-count distribution, so the intermittent count is directly auditable.

## Label and model purpose

The six-year extension defines the label directly as `w_flag = 1 when W > 0`; it is not generated by a W-mark-share quantile threshold. Only the older three-year experiment used the 75th percentile of the derived-share compatibility field `W_proxy`; because q75=0 with many tied zeros, it used strict `W_proxy > 0` to preserve both classes. Both are review-priority screens, not deployment guarantees, official probabilities, or causal effects.

Logistic regression is the interpretable primary model: it is stable and fast for moderate data and its coefficient directions are readable. Random forest (RF) is a fixed-parameter nonlinear comparator used to check whether interactions and ranking add limited value; a one-off holdout win does not make it a deployment model.

## Metrics, confusion matrix, and hand calculation

Let TP correctly identify a W, FP be a false W alert, FN miss a W, and TN correctly identify no W:

- `Precision = TP / (TP + FP)`: how often a W alert is correct.
- `Recall = TP / (TP + FN)`: how many true W rows are found.
- `F1 = 2 × Precision × Recall / (Precision + Recall)`: harmonic mean of precision and recall.
- `Specificity = TN / (TN + FP)`; `Balanced accuracy = (Recall + Specificity) / 2`.
- `ROC-AUC`: ranking discrimination over thresholds; not accuracy.
- `AP` (Average Precision): a precision-recall ranking summary accumulated from high to low scores; more informative than accuracy under class imbalance.
- `Brier score = mean((predicted probability - actual 0/1 label)^2)`: lower is better because probability calibration error is smaller.
- `Recall@20%`: the share of true positives covered when reviewing only the top 20% of scored rows.

Hand calculation: if TP=8, FP=2, FN=4, TN=86, Precision=8/10=0.80, Recall=8/12≈0.67, Specificity=86/88≈0.98, F1≈0.73, and Balanced accuracy≈0.82. This example explains formulas only; it is not a project result.

The old model's actual 2023 holdout records are included for historical interpretation:

| Model | TP | FP | FN | TN | Recall@20% |
| --- | ---: | ---: | ---: | ---: | ---: |
| Logistic Regression | 465 | 1,166 | 143 | 1,266 | 47.9% |
| Random Forest | 337 | 411 | 271 | 2,021 | 48.4% |

Old-model Brier scores were majority baseline `0.160` < RF `0.171` < Logistic `0.274`. This says RF was better calibrated than Logistic in that run, not that it created causal or deployment gains. AP, ROC-AUC, F1, and other values should be read from the generated holdout table for the current window; old values must not be copied into a new window.

## Logistic encoding and coefficients

Numeric features are median-imputed and standardised using training data. A numeric coefficient describes the direction and size of the change in W-label log-odds for a one-standard-deviation increase, holding other features fixed. A positive sign is the higher-log-odds direction; a negative sign is the reverse. `abs(coef)` ranks features only within this model, not across models. `odds ratio = exp(coef)`.

Categorical features use one-hot encoding; each comparison must state its reference category. Coefficients describe model associations, not a causal effect of scheduling or teaching on W. Course scale, grade-record structure, historical demand, and the W-mark share can share measurement sources.

## K-Means course-volume profiles

K-Means is an exploratory course-volume appendix, not a predictor, and currently has no strong decision value. The process is:

1. use train-period course aggregates only, keeping holdout information out;
2. median-impute and standardise numeric features;
3. run `K=2..5`, each with `n_init=20`;
4. use standardised Euclidean distance and select K by the highest silhouette;
5. treat each centre as a mean vector, not a manually assigned course type.

The current separation is mainly ordinary versus very large volume. `Students=grade_total`, and historical demand is approximately Students with repeated weighting; W centres are close. Therefore clusters are not student groups, withdrawal causes, or causal categories.

## Anomalies and limits

W observations in 2020 Fall / 2021 Spring are anomalous and should be flagged for data review, not automatically explained as policy, teaching, or student-behaviour changes. GPA aggregates have no student ID, section times, capacity, waitlist, attendance, LMS events, or registration/withdrawal timestamps. The derived W-mark share is therefore not an official withdrawal rate, and models can report only associations and screening performance.

## Same-course panel modelling and continuity

The trajectory model uses stable key `Subject + Number` as the course identity and keeps each Spring/Fall observation in the same course panel. The continuity focus is 2021–2023, with 2024 serving as bridge history and a truth-only holdout. Course titles are display-only and title changes are audited rather than used to split a course number. The current exclusion is 34 special/selected-topic raw records touching 11 stable keys: 3 keys are special-only and fully outside the ordinary trajectory, while 8 keys also have ordinary-course records that remain included. This is row-level handling; overlapping keys are not removed as a whole. Ordinary courses use either Spring/Fall from each prior calendar year; genuinely one-season courses use the same season. The implementation does not create separate unrelated models for `course_id + term`.

`course_trajectory_continuity.csv` records observed years and terms, coverage of the 12 possible terms, the exact `observed_periods`, 2021–2023 observed-year count, the history matching mode, training/backtest eligibility, and an exclusion reason. A fully observed course is `continuous_both_terms`; a course observed in one season is `seasonal_spring` or `seasonal_fall`; other incomplete sequences are `intermittent`. Missing offerings are not filled with zero. Rows without three prior eligible calendar-year observations are explicitly excluded rather than hard-predicted. The regenerated ordinary-course counts are 317 continuous-both-terms, 174 fall-seasonal, 128 spring-seasonal, and 2,981 intermittent out of 3,600; the intermittent count is auditable from each course's observed cells and period-count distribution.

The six-year extension predicts `w_flag = 1 when W > 0`. The prediction table contains the model score, the actual 0/1 outcome, `prediction_error = score - actual`, and absolute error. This is a binary screening target, not a continuous demand forecast, so no calibrated interval is claimed. `w_mark_share` may be used descriptively and as historical input, but it cannot be used to infer pass rate, official GPA, or withdrawal cause.

## W, drop, and grade-field boundaries

The source actually contains `W`, `Students`, and A+ through F grade-count fields. `W` means the count of formal `Withdraw` marks in the grade-distribution record; `Students` is the count of final A+–F grade records after course completion, and the source field equals the sum of the A+–F bands. It is not registrations, unique students, or section enrollment; a course-level aggregate may contain records from multiple instructors. The data contains no drop event, withdrawal timestamp, registration event, student ID, or official numeric GPA field. Therefore `w_mark_share = W/(Students+W)` remains a derived share, not an official withdrawal rate. W=0 means no W mark was observed in the aggregated final-grade records; it does not by itself prove no earlier drop, adaptation, or absence of a sudden difficulty change. `grade_point_mean` is only a documented estimate from letter-grade counts.

## Business interpretation and next data

The project owner’s business interpretation is that `W` is the formal
`Withdraw` mark left in the grade record after the no-W drop deadline. For a
standard 16-week undergraduate course, this may be described as a W left after
the halfway point (roughly week 8), but that business timing must not be
generalised to every course. Part-of-term, short, nonstandard, and graduate-
course deadlines differ. The current GPA file still provides only an aggregated
final W-mark count, with no withdrawal time, event, or event id; therefore the
source cannot establish when an individual W occurred.

The desired next dataset is a section-level panel with the same
`CRN/section_id` observed twice: an opening-week roster/enrollment snapshot and
a post-add/drop (approximately week-two or official census) snapshot. Their
difference would be a rough **net enrollment change**, not a gross drop count,
because late adds, section transfers, cancellations, cross-listing, and
different part-of-term start dates can also change the count. Required fields
include `term`, `CRN/section_id`, `Subject`, `Number`, `snapshot_date`,
`enrollment_count`, `capacity`, `part_of_term`, and cancellation/merge flags.

We found partial public sources, not the complete paired panel. Illinois DAIR
explains that rosters update daily but public enrollment reporting uses a
census snapshot on the 10th day; Enrollment Management publishes 10th-day
reports; DMI exposes some historical course/section enrollment tables. We did
not find a reproducible public first-week plus second-week section time series.
Daily rosters and registration activity reports are authorized campus services,
so access would require an institutional request and FERPA-appropriate
controls. See the [DAIR enrollment FAQ](https://dair.illinois.edu/faqs-updated/enrollment-faqs/),
[10th-day reports](https://enrollmentmanagement.illinois.edu/reports-data/),
and [DMI section-enrollment examples](https://www.dmi.illinois.edu/cp/listcourses.asp?org=1B1-KV-XXX-XXX&row=6540&year1=2023&year2=2024).

The proposed ideas that high A/A+ share, easier grading, required-major status,
or “water-course” status changes W behavior are hypotheses, not current
findings. The file has letter-grade counts but no official numeric GPA and no
official easy-course label. The generated `grade_point_mean` documents a
weighted grade-profile estimate, but it must not be presented as an official
GPA or a causal explanation. The file also includes `Primary Instructor`; since
a course-term may contain multiple instructors and no section id, instructor
names are retained as audit context rather than treated as a causal difficulty
measure.

## Why K-Means is exploratory only

K-Means is intended to find similar course-volume profiles from numeric features, not student groups or withdrawal causes. A centre is the mean feature vector for a cluster; standardised Euclidean distance measures similarity to that centre. Severe class-size imbalance can occur when a small number of courses are much larger than the majority, or when multiple scale features repeat the same signal; it does not mean the small cluster is riskier. The current separation is mainly ordinary versus very large volume and W centres are close, so it has no actionable withdrawal interpretation. It is retained as an exploratory visual/data-audit appendix, not a core conclusion or decision label.

## Statistical methods that fit the current data

Reasonable extensions are Spring/Fall-stratified trend and seasonal summaries; hierarchical aggregation by course, Subject, and term; denominator-aware W-mark-share intervals or sensitivity ranges; descriptive profile groups; change-point/stability checks for unusual periods; and observed-volume-versus-supply comparisons once licensed capacity or waitlist fields exist. Without capacity, registration events, section times, or event timestamps, do not claim crowding, causal schedule effects, student-level survival models, or complex deep time-series models. Results remain observational associations.
