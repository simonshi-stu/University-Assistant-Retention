# 看板变更边界与用户体验约束

本文件是后续代理修改 `dashboard/app.py`、README 和看板说明时的约束。目标是补齐解释与证据，不重做现有看板的视觉设计。

## 允许的变更

- 修复用户可见的口径、标签、单位、筛选联动和结论说明。
- 为每个页面增加简短的“看什么 / 结论 / 限制”说明。
- 补充数据存量、字段含义、缺失字段、解决路径和未来路线。
- 让 Top-N 只影响明确标注的榜单，并在标题或 caption 中写清作用范围。
- 使用已生成的报告和表格解释模型、画像和数据覆盖，不在浏览器中重新训练模型。
- 在不扩大数据授权范围的前提下补充数据源说明和复现提示。

## 不允许的变更

- 不随意改变现有页面结构、配色、宽屏布局、图表类型或筛选器位置。
- 不把 W 代理写成官方退课率、把 Students 写成独立学生数，或把 GPA 聚合写成 section/attendance 数据。
- 不捏造出勤、参与人数、容量、waitlist、注册事件、评论情绪或排课冲突结果。
- 不在看板用户可见文字中出现内部阶段编号、阶段完成情况、内部 JSON/报告文件名或 agent 执行过程。
- 不让筛选器悄悄改变固定的训练集、留出集、标签阈值或模型参数。
- 不将 K-Means 簇解释为学生群体、退课原因或因果类别。
- 不用 2026 年或更晚的数据，也不绕过学校登录、WAF 或服务条款获取数据。

## 固定的用户说明

看板需要持续说明：

1. 它使用的是公开 UIUC GPA 的课程-学期聚合数据；
2. `demand_proxy = Students + W`，`W_proxy = W / (Students + W)`，两者都是描述性代理；
3. 当前没有学生级 attendance/LMS、section 时间、容量、waitlist 或注册事件数据；
4. 模型结果是时间留出集上的筛查表现，不是因果效果或部署保证；
5. 当前 K=2 的画像主要体现课程规模差异，不能解释退课原因；
6. 五个排课问题必须逐项给出“可回答”或“数据不足 + 缺失字段 + 可行替代路径”。

## 变更后的最小验收

- `pytest -q -p no:cacheprovider` 通过；
- `dashboard/app.py` 可以编译并在已有输出上启动；
- 年份、学期、院系筛选仍有明确作用；
- Top-N 变更能影响所有标注的榜单，固定图表不会伪装成动态榜单；
- 看板没有内部阶段词或执行过程词；
- 页面数值、单位、标题和 README 与 `data/processed` 产物一致；
- `HISTORY.md` 记录本次变更与验证证据。
